## 1. 项目一句话

**《逃离考场》**：在 Unity 中做一款第三人称、中国高考文化叙事下的「潜行逃出考场 → 逃出学校 → 乘交通工具去各地旅行做任务」原型。

**当前可玩**：v0.1–v0.5 + **v0.6 连通校园大地图 CampusWorld**（同场景考场→走廊→楼梯→校门→公路/城镇；默认 Play 入口）（Netcode Host/Client、分考场 spawn、汇合点；非完整联机产品）。OSM、精美美术、Relay/匹配/语音仍未合入。

- **仓库（私有）**：https://github.com/fangfangzhouhang/gta-style-unity-prototype
- **GitHub 账号**：fangfangzhouhang
- **引擎**：Unity（用户本机有环境）
- **当前 main 可玩切片管线**：Built-in Render Pipeline + 旧版 Input Manager（`Input.GetAxis` / `Input.GetKey` 一类）
- **曾讨论过的目标方向**：URP、OSM 真实地图等仍未合入；**Netcode 联机骨架**见 v0.5 分支（需 Package Manager 解析 `com.unity.netcode.gameobjects`）
- **交接时请先 `git log -1` 核对 HEAD**；以仓库为准，并以本 Docs 描述的「可玩范围」做验收。v0.4 合入后基线以含 `HubTown`/`Home`、`TeacherAgent`、`SaveSystem`/`PauseMenu`、购票门槛与 `Assets/Scripts/AI|Progress|Economy|Home|Hub|Map` 的提交为准。v0.5 联机骨架基于 `feature/escape-exam-v0.4-chase-save-travelgate` 拉出；**建议先合 PR #4（v0.4）再合 v0.5**。

## 5. 环境与如何在 Unity 打开验收

### 环境假设

- 用户已安装可用的 Unity Editor（具体版本以仓库 `ProjectSettings/ProjectVersion.txt` 为准；交接文档不臆造版本号）。
- 仓库为私有，需要 GitHub 访问权限。
- 渲染管线：**Built-in**；输入：**旧 Input Manager**。

### 建议验收步骤

0. **推荐入口**：打开 `Assets/Scenes/CampusWorld.unity` 直接 Play（或菜单 **EscapeExam → 生成连通校园大地图** 后重建）。无需先生成多个空场景再跳转。
1. 克隆仓库到本机，用 Unity Hub / Editor 打开项目根目录（含 `Assets/`、`ProjectSettings/` 的那一层）。
2. 等待导入完成；若有 Console 报错，先记录再修，**不要**在未跑通基线时大改架构。
3. 打开 `Assets/Scenes/OpenWorld.unity`。
4. 若场景缺失或为空：使用菜单 **OpenWorld → 生成占位场景**（以编辑器实际菜单名为准），再进入 Play。
5. Play 模式验收：
   - WASD 移动角色；
   - 靠近载具按 **F** 上车，再按 **F** 下车；
   - 驾车进入黄色任务区域，确认「任务完成」提示出现。
6. 将结果勾进 `07-待验证清单.md`，并向用户简短汇报。

### 不建议的操作（除非用户明确要求）

- 一上来切换 URP / HDRP
- 一上来换成新 Input System 包并删除旧输入
- 引入未授权商用资源
- 启动云端重渲染 / 大模型批量生成资产
- 假设 v0.2 代码已在某远程分支

## 7. 给代理的工作约定

1. **交流语言**：与用户、交接文档一律使用**简体中文**；代码标识符可英文，面向用户的 UI 文案用中文。
2. **私有仓库**：勿把仓库内容、密钥、内部讨论发到公开渠道；PR / push 权限遵循用户安排。
3. **真相源**：以 GitHub 上已推送代码 + 本 `Docs/` 为准；未推送的实验默认无效。
4. **范围控制**：先做可玩小切片；禁止把「饥荒式生存」「枪战警察大而全」当成第一优先（见 `01`）。

7. **Skills**：改 Unity 工程前，先在 `.agents/skills/` 查找匹配 skill 并遵循其流程；没有 skill 覆盖的领域再自行谨慎实现。
8. **文档同步**：完成一个可演示里程碑后，更新 `00` 的已完成清单与 `07` 勾选状态，避免下一位接手再次踩空。
9. **不要编造进度**：未实现功能不得写进 README「已支持」列表。

## 8. 已知坑

### 8.1 输入法「吃掉」F 键

- 中文输入法开启时，按键可能被 IME 拦截，导致 **F 上下车** 无响应。
- **验收 / 演示时**：切换到英文输入，或关闭 IME 后再测。
- 后续若改输入，可考虑在 UI 提示「请使用英文输入法」，或评估新 Input System 的 IME 行为（属改造项，非当前必做）。

### 8.2 URP / 管线切换后的粉色材质

- 当前可玩基线是 **Built-in**。
- 若项目或材质被按 URP 导入 / 升级，常见现象是材质变粉（Shader 不匹配）。
- **处理原则**：未获用户批准前不要升级管线；若已粉，优先恢复 Built-in 材质 / Shader，而不是强行「修成 URP 工程」。

### 8.3 Input System 包与旧 Input Manager 混用

- 基线代码面向**旧 Input Manager**。
- 若 Package Manager 里启用了新 Input System 且 Player Settings 设为「Only New」，旧 `Input.Get*` 会失效或报错。
- **建议**：保持与 README / 工程一致的旧输入设置，直到专门做迁移里程碑。

### 8.4 把愿景当成已实现

- 「联机、OSM、真实票务」等仍是方向，不是可玩现实；高铁/旅行已有**极简占位**，勿夸大。
- 验收只认：能 Play 的操作与仓库内脚本。

### 8.5 v0.2 / v0.3 场景串联注意

- 考场成功 → `SchoolEscape`；学校成功 → `TransitHub`；枢纽检票 → `TravelMissions`。
- 均需在 Build Settings（菜单 **EscapeExam → 将场景写入 Build Settings** 可修复）。
- 空场景请先跑生成菜单；仅有 Bootstrap 的场景在 Play 时也会自动 `Build()`。

### 8.6 占位场景与菜单依赖

- 若 `OpenWorld.unity` 被误删，应优先用 **OpenWorld 生成菜单** 重建，而不是手搭一套不一致的场景。
