## 2. 潜行（建议 · v0.2 · 未实现）

### 2.1 目标体验

玩家靠观察监考视野、利用掩体与蹲走，从座位移动到出口；被发现则失败重试，而不是战斗杀敌。

### 2.2 建议规则

- **视野锥**：监考前方扇形；玩家进入且无遮挡 → 警戒值上升或直接发现（第一版可直接发现，降低调参复杂度）。
- **蹲走**：降低移动速度；进入「矮掩体后不可被看见」或缩小被发现判定（二选一，第一版建议：蹲 + 在掩体 Collider 后 = 安全）。
- **掩体**：桌斗、书柜、墙角占位盒子即可；需有清晰可读外形。
- **失败**：UI「被发现了」→ 淡出 → 重生到检查点（座位或走廊门）。
- **成功**：触发 `ExamEscapeSuccess` 一类事件，再加载学校段。

### 2.3 建议调参入口（便于策划改）

- 视野角度、距离、发现所需时间；
- 蹲走速度倍率；
- 检查点 Transform。

### 2.4 明确不做（v0.2）

- 复杂光照 thruster、声音传播模拟、多智能体群体战术——可后期再加。

## 3. 学校逃离（建议 · v0.2 · 未实现）

- 结构：线性关卡 + 少量可选侧路径。
- 威胁：1–2 种巡逻占位 AI（可用与监考相同的视野锥组件复用）。
- 终点：校门触发器 →「逃出学校」→ 打开交通枢纽或临时回到 OpenWorld 并解锁标记。
- 与考场共享：输入、失败重试 UI、中文提示风格。

---

## 4. 载具与任务点（已有 · 可扩展）

### 4.1 已有

- 上车 / 下车：F；
- 驾驶至黄色区域完成任务。

### 4.2 扩展建议（未实现）

- 多种任务类型：到达 / 交互 / 护送占位 NPC / 限时到达；
- 任务数据用 ScriptableObject（`MissionDefinition`）描述标题、说明、目标点、完成事件；
- UI：任务追踪面板（左上简短中文）；
- 保持黄圈作为「主目标可读性」的第一语言，颜色盲友好时可再加图标。

## 5. 交通枢纽流程（建议 · v0.3 · 未实现）

极度简化即可，避免做成票务模拟器：

1. **购票**：靠近窗口按 E → 面板显示车次「G-自由 01」→ 确认获得 `Ticket` 布尔或道具。
2. **检票**：靠近闸机，有票则开门/淡出，无票则提示。
3. **乘车**：加载下一场景或启用旅行区。

地铁 / 机场可用同一状态机换皮（文案与模型不同）。

## 6. 联机（建议 · v0.5 · 未实现）

### 6.1 技术建议

- **Netcode for GameObjects**（NGO）作为默认讨论方案；最终以用户批准为准。
- 先做「同场景少量玩家 + 主机权威」，不要先做专用服务器。

### 6.2 玩法建议

- **不同考场 spawn**：每人自己的考场实例（或同场景分隔房间 + 隔离视野）；
- **潜行阶段**：尽量少同步他人位置给仍在潜行的玩家（防破坏体验）；或接受简单同步但禁用干扰技能；
- **汇合点**：逃出成功后启用共享世界层，黄圈汇合；
- **断线**：友好提示，允许重连回汇合区（细节实现时再定）。

### 6.3 非目标（联机第一版）

- 反作弊、匹配大厅美化、跨平台语音——均可更晚。

## 7. UI / 镜头 / 输入约定（跨版本）

| 项 | 约定 |
| --- | --- |
| 语言 | 玩家可见文案简体中文 |
| 输入（当前） | 旧 Input Manager；WASD + F（+ 潜行后建议加 Ctrl 蹲、E 交互） |
| 输入法 | 文档与启动提示中说明使用英文输入法 |
| 镜头 | 第三人称；潜行可微调整；不要第一版就做完整镜头编排器 |
| UI | 少而大：任务、提示、失败、成功；避免 MMO 式满屏 |
| 暂停 | Esc 暂停（若未做，v0.2 可补最小暂停） |

## 10. 验收口径（设计是否做对）

- 新系统是否能在 5 分钟内向用户讲清「怎么玩、怎么赢、怎么败」；
- 是否仍能一键回到 OpenWorld 演示 v0.1；
- 是否没有把未实现功能写进 README 已完成区。
