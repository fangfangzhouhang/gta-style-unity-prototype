# 资源来源与许可

## 1. 原则

1. **禁止**使用未授权的商用资源（含「从某网盘下的付费包」「撕破版权的模型」「未购授权的音效」）。
2. 优先 **CC0 / 公共领域 / 明确可商用且条款清晰** 的资产。
3. 每个进仓库的第三方资源必须留下记录（见文末模板）。
4. 开源可商用 ≠ 无条件：仍要看是否要求署名、是否 ShareAlike、是否禁止 AI 训练等附加条款（以资源页当时条文为准）。

## 3. 推荐来源（可商用取向，使用前仍要点进条款页确认）

下列为团队讨论中常见的**推荐方向**，不是「已经全部导入仓库」：

| 来源 | 常见内容 | 常见许可取向 | 使用提醒 |
| --- | --- | --- | --- |
| **Kenney.nl** | UI、原型模型、音效、粒子 | 多为 CC0 | 下载页确认；Credits 可感谢 |
| **Quaternius** | 低模角色 / 环境 | 多为 CC0 | 确认具体包条文 |
| **Poly Haven** | HDRI、纹理、部分模型 | 多为 CC0 | 大文件勿未经商量批量下载占满磁盘 |
| **ambientCG** | 材质纹理 | 多为 CC0 | 同上 |
| **Unity Asset Store — 标明免费且许可允许** | 插件 / 模型 | 以 Store EULA + 资产页为准 | 有的「免费」限制再分发，注意 |

**OSM 数据**：见 `04-文化与环境研究.md`；ODbL 与游戏资产 CC0 不是同一套规则。

## 4. 禁止与灰区

- 未购买的付费包、泄漏资源、爬取商业游戏资产；
- 未授权的品牌商标拿来当关卡招牌（可改用虚构招牌）；
- 「AI 生成资产」若用户未批准重任务 / 未确认训练数据与商用条款，默认不要进主仓（见 `06`）；
- 字体：不要随便塞「某办公套件字体」进项目。

## 5. 入库记录模板

在 `Docs/licenses/` 或资源旁 `LICENSE_NOTES.md` 追加（路径可自定，但要有一处集中表）：

```markdown
### 资源名称
- 来源 URL：
- 作者 / 发布方：
- 下载日期（Asia/Shanghai）：
- 许可名称与链接：
- 是否要求署名：是/否（若是，署名文案：）
- 使用位置（场景/预制体路径）：
- 备注：
```

字体额外检查：

- 是否包含 `LICENSE` / `NOTICE` 文件；
- 是否允许嵌入游戏客户端。

## 7. 接手动作

1. 打开工程后搜索 `.ttf` / `.otf` / 第三方插件目录，对照本节补全「现有已知资源」。
2. 新增资源必须走记录模板，否则 PR 不算完成。
3. 不确定许可时：**先问用户**，不要「先用后补」。
