# 重任务方案

> **当前默认：不做。**  
> 凡标注「需用户拍板」的事项，代理不得自行开工、不得自行租用 GPU、不得自行发起长时间渲染或大规模生成。

---

## 1. 什么叫「重任务」

在本项目中，重任务指至少满足下列之一：

- 需要**大模型 API** 批量生成文案 / 贴图 / 代码以外的内容，且费用或配额明显；
- 需要**GPU 训练**或微调（音色、图像、策略网络等）；
- 需要**重渲染**（高分辨率影视级预渲染、大规模光照烘焙农场、长时视频导出流水线）；
- 需要**大规模数据抓取 / OSM 全国级处理**，占用大量磁盘、带宽或合规审查；
- 预计单次耗时数小时以上且会阻塞用户机器日常使用。

轻量、本机可快速完成的工作（写脚本、搭占位场景、调视野锥、做简单 UI）**不属于**重任务。

## 3. 拍板前代理必须提交的说明（模板）

向用户请示时写清：

1. **目标**：要解决什么玩家体验问题？
2. **替代轻量方案**：不用重任务能否先做 80 分占位？
3. **成本**：预估时间、是否花钱、是否占用用户 GPU / 磁盘；
4. **风险**：许可、不可复现、污染 git 历史、粉材质 / 大二进制；
5. **回滚**：失败如何恢复 main 可玩性；
6. **验收**：用户如何一眼看出「值得」。

未获得明确同意前，保持默认：**不做**。

## 4. 与里程碑的关系

- **v0.2 潜行 + 学校**：应用规则、占位几何、手写短文案即可，**不需要**重任务。
- **v0.3–v0.4**：交通与旅行任务仍可手搓；仅当内容量爆炸时再讨论 H1。
- **后期精美化 / OSM**：再打开 H5、H6 讨论。

## 5. 历史教训（必读）

云端代理 v0.2 尝试曾因**编译错误中断并被取消**，代码**未推送到 GitHub**。  
因此：

- 不要假设重任务流水线「已经搭好」；
- 不要在无用户批准时重新拉起同等规模的自动改仓；
- 任何实验分支以用户可见的小 PR 为单位。
