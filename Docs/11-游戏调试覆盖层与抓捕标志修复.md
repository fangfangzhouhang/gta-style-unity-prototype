# 游戏调试覆盖层与抓捕标志修复

2026-10-21。用户截图：Game 视图叠加了蓝色导航调试图形及 Unity Light 灯泡图标。

## 修复

- 新增 `CampusPresentationSettings`。脚本加载、打开 CampusWorld、进入/退出 Play 时恢复正常游戏画面，关闭 Game 视图 Gizmos、导航网格及导航辅助覆盖层。生成场景的入口同样调用此修复。
- Unity 2022.3 的导航绘制开关为内部编辑器属性，按该版本官方 C# 参考源码检查后使用反射设置。兼容查询缺失属性，不引用旧的无效 showNavigation 计数。
- 隐藏 Light 组件内置图标。抓捕者的灯光标志改由 `ScrutinyAura.OnGUI` 独立绘制，普通灯管不挂此组件，因此不会出现标志。
- 标志位于抓捕者头顶，平时黄色、追逐时红色，家长为紫色。距离超过 24 米、被墙遮挡、位于视野外或打开暂停/地图时隐藏。
- 菜单兜底：**EscapeExam → 显示 → 恢复正常游戏画面（隐藏调试网格）**。

## 验证

在隔离验证工程执行 `CampusPresentationSettings.Validate`，先打开 showNavMesh 和 GameView.drawGizmos，再调用恢复逻辑，验证两者均为 false，且抓捕者标志绘制函数存在。

日志：`D:/Unity/campus-presentation-validation.log`，包含 `CAMPUS_PRESENTATION_VALIDATION_PASS`，编译和 batchmode 退出成功。主编辑器载入新脚本后会生成 `D:/Unity/CampusValidation/presentation-status.txt` 状态记录；Game 视图有可读渲染纹理时额外保存 `presentation-gameview.png`。

若编辑器处于后台，切回 Unity 让它刷新脚本，再重新 Play。该修复修改编辑显示和角色标志；场景模型和导航数据继续用于正常渲染与寻路。

源码参考：[Unity 2022.3 NavMeshVisualizationSettings](https://github.com/Unity-Technologies/UnityCsReference/blob/2022.3/Modules/AIEditor/Visualization/NavMeshVisualizationSettings.bindings.cs)、[Unity 2022.3 GameView](https://github.com/Unity-Technologies/UnityCsReference/blob/2022.3/Editor/Mono/GameView/GameView.cs)。
