## 手账和输入

`CampusJournal` 从既有章节布尔事实生成线索与道具列表，不再维护一份重复物品数据库。未读试卷 / 座位表不进入列表；未查图书馆记录不出现 086。区域到访由实际角色位置及当前区域权限记录到 `journal.visited`，开放状态继续取自实体门禁事实。

提示不自动弹出，点“请求下一级提示”才递进；看提示不会把线索标记为已调查，也不会发物品或开门。三级提示可以解释下一步动作；正式线索列表仍只显示已发现内容。提示级别属于临时 UI 状态，不随存档保留。手账可滚动，文字高度随换行计算，采用不透明度较高的深色背景。

当前目标在校园内复用 Director；章节结束后的城镇 / 家庭目标复用原 HUD 数据。手账打开时隐藏校园 HUD 和字幕，避免重叠。移动控制、Time.timeScale、鼠标显隐 / 锁定在关闭时恢复到打开前状态；骑行中不允许打开手账。Esc 同帧标记避免先关一个面板又开暂停。旧暂停菜单“退出到标题”实际加载 HubTown，而非独立标题画面；本阶段在章节完成前阻止该场景切换及联机大厅切换，并给出反馈，保留保存 / 读取 / 退出游戏；完成后恢复切换权限，避免从暂停菜单绕过所有实体门禁。

## 叙事事件和声音接口

`CampusNarrative.Emit(id, channel, text, seconds, once)` 是轻量入口，支持 Inner / Broadcast / NPC / Feedback。关键事件包括 intro、window、key、side、corridor、room203、circuit、archive、emergency、gate、departure、complete。

一次性事件 ID 记录在 `narrative.played`，相同 ID 不重播；重复 NPC 线索与调查使用可重复消息。字幕按队列显示，退格键跳过当前条目；加载存档清除旧运行队列，再按持久化事实继续。这里保存的是事件已触发状态，不是音频听完进度。

保留兼容的 `CampusExamChapter.ShowSubtitle` / `ShowEvent`，已有章节改为通过统一组件输出；旧场景没有该组件时仍保留原字幕回退。密码界面不与叙事面板抢鼠标或覆盖手账。

提供可绑定的 AudioSource、按事件 ID 配置的 AudioClip 引用、环境音源引用与 onLine 回调；没有加入或声称拥有合法配音、环境音演出。资源为空时仍有完整中文字幕。后续声音工作需提供合法素材并配置，不能只绑定空引用就勾选“配音完成”。

## SaveData v2

新增字段：

| 字段 | 含义 |
| --- | --- |
| version | 当前为 2，缺失的旧 JSON 按旧版迁移 |
| journal.visited | 实际到访区域 ID 列表 |
| narrative.played | 已触发的一次性事件 ID 列表 |
| checkpointId | 已命名的校园检查点，优先于旧坐标匹配 |
| hasPlayerPose | 是否保存可直接恢复的步行姿态 |
| playerX / playerY / playerZ / playerYaw | 保存位置和水平朝向 |

原四组章节状态、经济、手机、留条、票据、地图、stage、sceneName 和旧检查点坐标均保留。`GameProgress.ToSaveData` 调用 `CampusSaveRestore.Capture`，保存正常步行姿态及当前检查点；被抓过程或骑乘时不保存附着在车辆上的人物姿态，读取后回到合法检查点并恢复步行，**不恢复车辆速度或自动重上车**。

迁移规则在 `CampusSaveMigration`：

1. 对非 CampusWorld 旧场景仅补缺省结构，保留原切片流程。
2. CampusWorld 的旧未离校档若没有章节字段，保留经济 / 手机 / 留条等资料，从锁闭 201 安全重启新章节；不能凭旧坐标跳到未开放区域。
3. 旧已离校档保持已完成，补齐新关卡必要事实和完成状态，回到校外合法检查点，防止已完成玩家被新锁困住。这是显式兼容规则，不能视为新游戏实际调查过全部线索。
4. 已有 V1.2 分阶段字段的旧档保留这些字段，缺失结构补默认值；根据既有事实补一次性事件记录，防止重播开场 / 解锁。
5. 迁移只在显式读取时应用；不自动覆盖或删除原玩家存档，下一次正常保存才写 v2。

`SaveSystem.LoadAndApply(true)` 在加载前检查场景可用性、关闭模态 UI，并把待恢复资料暂存在 GameProgress；新场景内 `CampusSaveRestore` 等各章节 Start 恢复门、灯、导航障碍后，再恢复姿态、区域、stage 和活动检查点。初始化顺序不再把最终状态留在 Exam。

位置需处于已解锁区域，有脚下支撑和站立净空，不能是 NaN / 无限值、地图外或未解锁楼层；不满足时用合法检查点。旧坐标可匹配合法检查点，否则按现有进度选择兜底。恢复后清理骑乘附着、垂直速度，教师回位，并给短暂无敌期。`LoadAndApply(false)` 继续保留“仅恢复数据与机关，不立即移动玩家”的既有语义。

## 验证方式与证据

完整路线继续使用 `CampusSceneValidation.RunFinalChecks`，新增密码打开时不能叠加手账的断言，保留原移动 / 碰撞 / 门禁 / 骑行测试。

独立 `CampusStage5Validation.RunChecks` 使用隔离存档，依次真正调用 `SaveSystem.LoadAndApply(true)` 并等待新场景恢复，覆盖十三种情况：201、走廊、203、图书馆、配电间、庭院、门外、骑行存档、旧未离校、旧已离校、旧 V1.2 部分进度、指向未开放楼层的非法姿态、新章完成档。核验位置 / 检查点、门禁、骑乘、叙事状态，以及旧经济资料。

同套检查验证未发现答案不进手账、三级提示、提示不修改发现事实、鼠标 / 暂停 / 地图互斥、Esc 消费、字幕队列 / 跳过 / 一次性事件。它是程序化接口验证，不等于实体鼠标或真人试玩。

执行模板（改为本机路径，三个批处理入口都自行退出，不加 `-quit`，必须先后运行）：

```powershell
& 'C:/Path/Unity.exe' -batchmode -projectPath 'D:/Path/ValidationProject' -executeMethod CampusSceneValidation.RunFinalChecks -logFile 'D:/Path/final.log'
& 'C:/Path/Unity.exe' -batchmode -projectPath 'D:/Path/ValidationProject' -executeMethod CampusStage5Validation.RunChecks -logFile 'D:/Path/reload.log'
& 'C:/Path/Unity.exe' -batchmode -projectPath 'D:/Path/ValidationProject' -executeMethod CampusLegacySceneValidation.RunChecks -logFile 'D:/Path/legacy.log'
```

Game 视图中的 IMGUI 截图需使用可显示的验证编辑器：`CampusJournalPreviewValidation.RunPreview`（不传 batchmode），自动打开手账并捕获后退出。静态场景渲染不包含 IMGUI；不能把空批处理截图当作手账验收。
