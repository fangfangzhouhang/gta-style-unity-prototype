以下为目标原文，不代表已经全部实现。当前实际状态见 [开发交接](../19-开发过程与后续交接.md)。

Unity《逃离考场》V1.2：封闭校园与逐层解锁式叙事逃脱

一、你的角色

你是一名具有成熟商业游戏制作经验的 Unity 游戏架构师、关卡设计师、潜行 AI 工程师和叙事设计师。

本次任务不是单纯生成更多建筑和 C# 脚本，而是将现有程序化游戏原型改造成具有正式游戏体验的第一章。

设计参考《你好邻居》的探索、解谜、追逐和逐步开启新空间的机制，以及《生化危机 2》的多层地图、快捷路线和区域回访设计。

不得直接复制参考游戏的模型、剧情、布局或受版权保护的内容。

三、项目目标

将当前游戏的主线设计成：

201 考场 → 二楼走廊 → 203 教室 → 三楼图书馆 → 一楼后勤与配电间 → 校园庭院 → 校门 → 摩托车 → 城市旅行。

游戏开始时，玩家被困在完全封闭的 201 考场。

* 门处于锁闭状态。
* 窗户可以看到外界，但不能打开、穿越或跳出。
* 玩家只能在已解锁的区域探索。
* 新区域必须通过物品、线索、解谜或特定事件开启。
* 已解锁区域可以反复返回。
* 玩家不能通过其他入口、旧传送器、碰撞漏洞或场景切换跳过前置阶段。
* 最终逃出校园后才能骑摩托车进入城市。

故事氛围从封闭、压抑、疑惑逐渐转变为紧张、探索、逃脱，最终释放为自由旅行。

不要把玩家一开始放入整张开放地图。

四、具体关卡设计

阶段 A：201 考场

开场播放简短旁白和校园广播。

玩家醒来，发现时钟停止，门已经上锁。

核心任务：寻找教室侧门钥匙。

设计至少三个可调查物件：

1. 桌面试卷：提供第一个信息。
2. 座位表或黑板：提供第二个信息。
3. 上锁储物柜：利用两个信息确定密码，打开后得到钥匙。

密码必须是固定、可解释、能够通过环境观察推导的答案。不可随机生成无提示密码。

教室内老师巡视，玩家利用桌椅躲避视线。

玩家取得钥匙后可以打开侧门。

未完成前，前门、侧门和窗户必须保持真实物理封闭。

阶段 B：二楼走廊

玩家第一次离开教室。

走廊必须有至少三名简单 NPC，其中至少一名可以提供主线线索。

NPC 可以在有限路径上行走、停留或交谈。

玩家通过公告栏及 NPC 对话得知 203 附近的储物柜藏有通行卡。

设计一个可以反复访问的线索 NPC，避免因错过对话造成死局。

教师在走廊巡逻，广播按钮可以吸引老师调查，从而提供通过危险区域的机会。

取得通行卡后打开 203 教室。

此时其余主要区域仍关闭。

阶段 C：203 教室

203 不应只是另一间普通教室，而应制作成具有特殊用途的维修设备室。

玩家找到维修记录，理解楼梯门的控制方式。

加入一个简单、有明确反馈的电路或开关谜题。

完成谜题后解除东侧楼梯门禁。

首次解锁时播放机关动作和音效，并更新当前任务。

阶段 D：三楼图书馆

使用书架、阅览区、档案柜、连廊和中庭视线建立区别于普通教室的空间结构。

设计至少一个必须结合环境信息才能解决的谜题。

玩家通过书籍编号及旧校园记录取得紧急门禁说明和维修钥匙。

开放回到二楼及通往一楼的可用路线。

允许玩家在新区域发现返回旧区域的捷径。

阶段 E：一楼后勤区域

配电间需要维修钥匙和门禁说明才能进入。

玩家启动紧急模式，解除教学楼的部分门禁限制。

加入明确的环境变化：

* 部分灯光熄灭或切换为应急照明。
* 校园广播播放异常提示。
* 附近教师进入调查状态。
* 原本关闭的庭院通道开放。

不得因为灯光变化直接导致 NavMesh 或关键机关失效。

阶段 F：校门与离校

玩家进入庭院并抵达校门控制台。

只有完成前面关键步骤后才能解锁校门。

校门解锁必须同时更新交互状态、Collider、导航障碍和场景表现。

触发离校事件后播放短暂旁白，解除摩托车的骑行限制。

保留现有 CampusMotorcycle 系统，不要重写驾驶代码。

玩家骑车驶离校园时展示章节完成效果，开启城市与旅行主线。

五、区域解锁系统

设计一个统一、可保存的区域解锁和谜题状态系统。

必须支持：

* 区域初始锁定。
* 物品与线索发现。
* 多个条件联合解锁。
* 永久与临时机关状态。
* 开门或关闭门禁。
* 任务状态更新。
* 存档读取后的场景恢复。
* 被抓捕后保留已获得的关键进度。
* 防止跳关与不可恢复的死局。

优先在现有 CampusEscapeDirector、CampusFlowController 与 GameProgress 上增量扩展。

可以引入 ChapterStage 枚举及轻量的谜题定义数据，但避免额外搭建庞大框架。

所有锁必须有明确的未解锁反馈。

不能只依靠 UI 判断是否通行。

六、线索手账与任务提示

新增或扩展线索手账系统。

按 Tab 打开。

至少包括：

1. 当前主线目标。
2. 已发现线索。
3. 已获得关键道具。
4. 已进入和未进入的区域。
5. 可选提示按钮。

线索只在玩家实际发现后进入手账，不提前显示谜题答案。

提示分三级：

* 一级：提示调查方向。
* 二级：提示相关地点。
* 三级：告诉玩家下一步可执行的操作。

提示可由玩家主动请求，不自动强制揭示谜题答案。

不能同时存在互相冲突的任务提示。

七、旁白与对话系统

新增轻量事件驱动的旁白系统，支持：

* 主角内心独白。
* 校园广播。
* NPC 对话。
* 任务完成反馈。
* 中文字幕。
* 可跳过的短对白。
* 同一事件默认只播放一次。
* 保存关键叙事事件触发状态。

例如：

开场：
“怎么还没有下课？这个钟，好像一直没动过。”

第一次查看窗户：
“明明能看到外面，却没有一扇门能出去。”

发现钥匙：
“终于有办法了。但门外似乎还有人。”

首次进入走廊：
“原来还有这么长一条走廊……出口到底在哪里？”

最终离开校园：
“我真的出来了。”

如果没有合法可用的配音资源，先实现完整的中文字幕和音频接口，不得声称已具备语音演出。

为每种旁白设置合适的触发事件，不要在每帧 Update 中重复播放。

八、NPC 与教师 AI

保留现有教师 AI 的 Patrol、Chase、Investigate 等功能。

根据需要增加搜寻最后已知位置的行为。

要求：

* 不隔墙发现玩家。
* 追逐支持楼层间 NavMesh 通行。
* 广播能吸引附近老师，但不能无限距离传播。
* 关键 NPC 线索可以重复获得。
* NPC 被暂时阻挡时能够恢复移动。
* NPC 不得永久堵死唯一出口。
* 玩家被抓捕后从最近检查点恢复。
* 不因为读档或重新进入区域导致 NPC 反复初始化错误。

第一版采用状态机，不引入在线大模型或不必要的机器学习训练。

九、场景与美术要求

不继续扩大地图面积。

重点优化 201、二楼走廊、203、三楼图书馆、一楼后勤区域、庭院与校门。

避免继续用同一个 Room() 模板生成大量同质化教室。

建议建立模块化资源：

* 墙体与墙角
* 门框和可开关门
* 带碰撞的窗户
* 楼板与天花板
* 楼梯与连廊
* 书架、储物柜、实验桌
* 灯具与机关
* 标识牌与线索道具

每个关键区域需要独立的视觉特征。

先确保空间比例、碰撞、交互与关卡路线正确，再进行高质量美术替换。

禁止未经确认直接替换 Unity 版本或迁移渲染管线。

十、兼容与安全要求

本任务必须遵守：

1. 创建独立功能分支，不直接修改远端 main。
2. 开始前记录当前 commit、分支及工作区改动。
3. 不覆盖任何未提交的本地修改。
4. 在重新生成 CampusWorld.unity 前备份场景。
5. 注意现有生成器可能清除 LevelRoot，禁止把新手工场景内容放入会被无条件销毁的位置。
6. 保留现有载具、城镇、家庭、旅行和联机骨架。
7. 不得删除第三方许可文件。
8. 检查多套 E 键交互脚本是否同时响应。
9. 不得因修改校园章节破坏旧独立场景的运行。
10. 对已有 API 的更改必须更新全部调用点与验证代码。

十一、执行顺序

按以下顺序增量实施：

第 0 步：只读审查

输出当前已有机制、新设计与现有代码的冲突、拟新增文件、拟修改文件和兼容风险。

第 1 步：封闭教室

实现初始区域物理封锁、钥匙谜题、开门及第一段旁白。

完成测试后提交。

第 2 步：二楼走廊和 203

加入 NPC 线索、通行卡、设备室解谜和局部追逐。

完成测试后提交。

第 3 步：图书馆与后勤区域

制作特色空间、楼层通行、档案线索、配电间和环境变化。

完成测试后提交。

第 4 步：校门与摩托车

串联最终解锁、校园离开、骑行和旅行章节入口。

完成测试后提交。

第 5 步：叙事、存档与验收

完善字幕、手账、环境音频接口、谜题存档、加载恢复和交互提示。

完成整个章节的端到端验证。

如果任何阶段暴露重大技术风险，优先修复，不要在未通过验证的状态下继续叠加功能。

十二、必须完成的验收

至少验证以下情况：

* [ ]	初始玩家只能在 201 教室探索。
* [ ]	通过任何窗户都不能离开教学楼。
* [ ]	未获得钥匙不能离开教室。
* [ ]	获取钥匙后可以打开正确的门。
* [ ]	走廊线索与 NPC 对话能推进调查。
* [ ]	203 未满足条件时不能进入。
* [ ]	完成 203 谜题才能打开对应楼梯门禁。
* [ ]	图书馆、楼梯、连廊可连续通行。
* [ ]	后勤区域存在正确的谜题前置条件。
* [ ]	未解除门禁前不能绕过校门。
* [ ]	解锁后校门能正常打开并通过。
* [ ]	早期不能骑摩托车或进入旅行区域。
* [ ]	玩家被抓后保留关键解谜进度。
* [ ]	保存并重新加载后，关键门锁和道具状态正确。
* [ ]	不会出现重复旁白、重复领奖或无限领取钥匙。
* [ ]	不会同时触发多个冲突的 E 键交互。
* [ ]	至少有两种有意义的局部路线选择。
* [ ]	原有摩托车驾驶和旧场景回归测试通过。
* [ ]	Unity 编译通过，没有新增严重异常。

保留现有校园自动测试，但调整它们以适应新的初始封锁与关卡路线。

不能因为旧自动测试不再适用，就直接删除测试。

自动化测试通过不等于玩家体验完成，还需要人工进行至少三次完整试玩，记录卡关原因、迷路情况和实际耗时。

7. 自动化测试结果。
